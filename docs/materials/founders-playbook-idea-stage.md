每一位创业者都从同一个地方开始：一个自己停不下来、反复去想的问题。Idea 阶段是想法碰到现实的阶段。2026 年的创业要成功，需要一种纪律：在证据足以支撑之前，先不要动手做产品。

这个阶段要做的工作是调研、客户发现、竞争分析，以及对反证做诚实评估。这些工作要在你让 Claude Code 写出第一行生产代码之前完成。

## Idea 阶段的目标

在 Idea 阶段，创始人的主要目标是以调研为导向的验证：在把资源投入到开发之前，先凑齐扎实证据，证明真实问题存在，并且你提出的方案能够有效解决这个问题。

从操作上看，Idea 阶段是创始人需要按大致这个顺序回答的一组问题：

- 这个问题是否真实、具体，而且频繁到值得围绕它去做产品？
- 到底是谁有这个问题，这些人能不能构成一个市场？
- 有没有别人已经在解决它？如果有，他们怎么做，做得怎么样？
- 一个解决方案真正需要做到什么，才能解决这个问题？我的想法能不能做到这些？

这些问题的答案会汇总成一个最终问题：这件事值不值得做？

这意味着你要先把问题说具体，再开始动手。「人们在报销上很费劲」只是一个观察。「中型公司的财务经理每周要花四个小时以上核对报销单，因为现有工具无法对接他们的会计软件」才是一个可以检验的假设。

## Idea 阶段的退出标准

Idea 阶段的退出条件是找到问题—方案匹配。你已经建立了定性证据，而且这些证据主要来自真实的人类对话：在你动手去做那个解决方案之前，你已经证明自己正在为一个真实的人解决一个真实的问题。

当你对下面三个问题都能回答「是」时，你就可以离开 Idea 阶段：

1. **问题是否真实而且具体？** 要给出肯定回答，你必须能准确说出：谁在经历这个问题、他们多久遇到一次、这个问题对他们影响有多严重、他们现在怎么处理它。
2. **你的方案是否针对实际问题？** 不是你最初假定的那个问题，而是验证过程揭示出来的那个问题。有时候两者相同，但并不总是如此。
3. **你是否已经有足够信号，足以支撑动手开发？** 在这个阶段你永远不会有确定性。等待确定性本身就是一种失败模式。但你需要足够的定性证据，让投入做一个 MVP 成为经过推理的决定，而不是一次信仰行为。

## Idea 阶段的挑战

Idea 阶段是创业旅程里最重要的工作发生的地方，因为最严重的错误也发生在这里：现在弄错一件事，很快就会把刚起步的公司带离正轨。这个阶段的大多数挑战，都来自行动速度快过你对问题的理解。因此，带着思考和克制往前走的创始人，会看到稳定的进展。

### 把「做出来」误当成「验证过」

挑战在于：当技术障碍被拿掉之后，一个热情很高的创始人可能跳过创业旅程里最重要的工作，也就是验证自己的想法是否真的是人们需要、并且会使用的解决方案。

即使在当前这轮 agentic coding 出现之前，也有 42% 的创业公司因为做了没人想要的东西而失败。现在，像 Claude Code 这样的 agentic coding 工具已经大幅缩短了「我有一个想法」和「我有一个产品」之间的距离。这个失败比例只会继续上升。

对一个脑子里有很强想法的创始人来说，现在是有史以来最好的时期。但快速、轻松地做出一个看起来像产品的原型，反过来也给 AI 原生创业公司带来了真实的生存风险。

直到最近，开发还需要真实的开发时间和预算。即使做一个基础原型，通常也要花几个月。现在技术开发这个门槛大体上已经消失了，AI 让创始人很容易直接跳进开发，却没有先验证这个东西在真实世界里有没有用。

要达到问题—方案匹配，必须先验证假设，再动手开发。但很多第一次创业的人，甚至有经验的创始人，会误以为 AI 已经绕过了这个要求，把流程变成：有一个想法 → 立刻做一个原型 → 把原型的存在当成验证。原型于是变成了相信假设一直正确的理由，而从未真正检验过这个假设是否成立。

一个能跑的原型很容易被误当成「你正在解决一个真实问题」的具体证据，但它不是。原型的真正用途，是作为压力测试的道具，用在和潜在用户的对话里。这些对话本身才是真正的证据。

### 过早扩张执行范围

挑战在于：当开发变得毫不费力、几乎即时完成时，你可以把执行规模推到远远超过业务实际需要的程度。

过早扩张执行范围，是指在你还没有真正验证这条产品路径值得投入之前，就已经沿着它走下去。

这向来会杀死创业公司。但 AI 让创始人更容易掉进这个陷阱，而且自己察觉不到。Agentic coding 助手非常强，以至于你可以在从未有意识地决定偏离路线的情况下，把执行规模推到远远超过问题—方案匹配的验证进度。

它会围绕一个根本上有缺陷的前提去生成、测试、调试、重构代码库，热情程度和面对一个好想法时完全一样。系统里的判断力来自你。这个阶段的首要指令是：让你的理解走在开发前面，尤其是当开发又快、又感觉毫不费力的时候。

### 失去客观性

挑战在于：如果你让 AI 工具去找支持你已有信念的证据，它会找到。确认偏误现在带着一套调研引擎。

确认偏误一直是创业的职业风险：创始人天生会对自己的想法充满热情。现在，AI 工具给确认偏误加了很大的功率。让 AI 验证你的创业想法，它会找到支持性证据；让它估算潜在市场规模，它会找到那个让你的 TAM 看起来能融到钱的数字。

AI 会顺着你给的方向走。这意味着，一个不提硬问题的创始人，现在可以比以往任何时候都更快地，为一个坏想法构造出一份看起来研究充分、结构精致的论证，同时完全自信地觉得自己正在做尽职调查。解药是同一套工具，只是指向相反的方向：AI 给一个想法做压力测试，可以和给它做正向验证一样彻底。

当调研和结构化对抗思考浮现出证据，说明你的想法需要修订时，这就是应该转向的信号。

## Claude 如何帮助 Idea 阶段的创始人

把一个 AI 原生创业概念推进过 Idea 阶段，可能会感觉永远走不完。你是创始人，你只想动手做。但这个最重要的启动阶段，本质上是调研和验证练习。这意味着你要先去拿那些能帮你更严格地思考的工具，再全力投入写代码。下面是在 Claude 的不同产品界面（Chat、Claude Cowork、Claude Code）上推进 Idea 阶段的方法：尽可能快地往前走，同时把该做的尽职调查做完。

### Chat、Claude Cowork 还是 Claude Code：选对 Claude 界面

AI 让创业者更容易更快交付、自动化乏味流程、按更大的规模运转。但你用哪个界面是有差别的。下面说明面对手头任务时，什么时候该用 Chat、Claude Cowork 或 Claude Code。

Chat 适合那种不用离开你已经在用的应用就能完成的快速往来。用它处理经营公司时不断出现的小事：从一份密集的投资人备忘录里抽出一句话结论，在董事会前核对一个说法是否站得住，或者搞清楚团队里一长串 Slack 讨论在说什么。

Claude Cowork 适合真正花时间的知识工作：从很多来源里取材料，把材料理清楚，再产出一份完成件，例如文档、演示文稿或电子表格。例如：把一文件夹客户通话记录整理成下一场产品评审用的主题发现文档；在融资前根据十几家供应商网站做出竞争格局图；或者设一个固定的周一上午任务，从已连接的工具里拉取指标，把周度 KPI 简报放到共享文件夹里。

Claude Code 是给团队里工程师用的 agentic coding 环境：直接访问代码库、Plan Mode、git 集成，以及本地、IDE 或沙盒云环境。精干团队在不断增长的代码库上交付功能、把 MVP 时期的遗留代码迁走、从原型走到生产，而不必等待更多编制，就是在这里完成的。

| 如果任务是…… | 用这个 | 原因 |
| --- | --- | --- |
| 一个问题、一次改写、一次快速头脑风暴 | Chat | 快、对话式、不用配置 |
| 调研、分析，或从你的文件和系统里做出一份完成文档 | Claude Cowork | 文件夹访问、连接器、skills、定时运行 |
| 编写、测试或交付软件 | Claude Code | 代码库访问、diff、git、开发环境 |

这三者底层是同一个 Claude；变化的是它周围的工作空间。

### 定义问题假设，并对它做压力测试

你自己的领域知识和前期调研已经生成了一个假设。第一项工作是把它打磨到真正可以检验。Claude 在这里特别有用的地方，是逼你说具体：到底是谁有这个问题、多久发生一次、有多严重、他们现在怎么处理？一个问题陈述如果不能精确回答这些问题，就还没有准备好去做验证。

- **练习：** 和 Claude 一起打磨你的问题陈述，直到它成为一个可以检验的假设。例如，「合同审核太慢」并不能构成有意义的可检验陈述。但「中型公司的内部法务团队每个合同审核周期要花 3 天以上，因为红线修改是在邮件线程里管理的，而不是在一份单一的、有版本控制的文档里」就非常可以检验。

接下来，让 Claude 反驳你的想法，并找出否定你假设的反证。这可以浮现负面市场信号、失败过的竞争对手、客户行为模式，以及结构性障碍。一份只负责支持你的综合材料，会悄悄把这些东西降级处理。

目标是：在进入客户发现之前，已经用当时能拿到的最强反驳，对你的假设做过压力测试。这样，信息型用户访谈才会真正开放，而不是变成一次寻找确认的过程。

说明：把 Claude 当作结构化唱反调的人来用，是 AI 创业生命周期每一个阶段的核心用法。

### 市场调研和竞争格局图

#### 摸清竞争对手

创业里有一种专门现象，叫做竞争对手忽视：你对自己的愿景和执行投入过深，以至于系统性地低估同一空间里其他人在做什么。所幸 AI 提供了解药：让 Claude 给出最有说服力的论证，说明为什么这个方案空间里的一个竞争对手会成功，而你不会。

Claude 可以分析：他们的做法为什么实际上更好，客户为什么会选他们，你自认为的差异化为什么可能没有你想的那么可防守。

- **练习：** 让 Claude 按层级画出你的竞争格局：直接竞争对手、间接竞争对手、潜在收购方，以及可能进入你这个空间的相邻玩家。然后让它论证每一层为什么构成对你成功的真实威胁，而不是那个最容易被你打发掉的威胁版本。

#### 市场调研

Claude Code 可以综合公开可得的客户反馈，浮现反复出现的抱怨和未被满足的需求。额外好处是：这件事本质上是在对竞争对手的客户做免费定性调研。

- **练习：** 让 Claude Cowork 综合你关键来源里的竞争对手评价，找出现有方案还没有解决的最主要抱怨。如果你的假设针对其中一条或多条，这就是问题—方案匹配的强证据。如果没有针对到，这一点本身也值得知道。

Claude Cowork 还可以从密集的行业报告、分析师文件和市场调研文档里抽出相关信息和数字。接下来，这些干净、经过综合的输入，会成为 Claude 分析工作的理想上下文。

- **练习：** 用公开可得的数据建立 TAM / SAM / SOM 模型，并对这些模型背后的假设做压力测试。判断市场是在扩张、整合，还是已经成熟；这个判断会影响你如何看待时机和差异化。画出买方格局：谁掌握预算，谁影响决策，这两者是不是同一个人。

#### 趋势分析

最后，用 Claude 去听早期信号，判断你是不是在正确的时刻进入。追踪那些已经在讨论你这个问题的 subreddit 和 LinkedIn 群组，以及用户描述自己问题时实际用到的原话。让 Claude 找出曾经解决过类似问题的类比市场，抽出什么有效、什么无效。浮现可能加速或威胁这次机会的监管、技术或人口趋势。

- **练习：** 让 Claude 找出三个外部趋势——监管、技术或人口——它们可能在未来两年显著影响你的市场，并评估每一个趋势对你这个具体假设来说是顺风还是逆风。

说明：这一节的市场调研和竞争格局工作不是一次性练习。你会在 MVP 阶段和 Launch 阶段继续发现新东西、继续修正自己的判断。因此，每当你的假设发生变化，就应该重复这些练习。

### 规划和设计客户发现

你和潜在用户交谈能学到什么，取决于两件事：（1）你问的问题质量如何；（2）你是不是在问对的人。Claude 在做客户发现时特别有帮助，包括该和谁谈、该问什么、以及如何理解你听到的内容。

#### 该和谁谈

一份精确的目标画像，价值远远高于一份很长的联系人名单。它应包括最可能强烈感受到这个问题的具体职位、公司类型、团队结构和资历层级。然后再找出这些人实际能被触达的地方——他们聚集的社区、活动、LinkedIn 群组和 Slack 工作区——并建立一个优先框架：根据他们离这个问题有多近，决定先联系谁。

#### 该问什么

目标确定之后，用 Claude 来搭建访谈框架本身：正确的问题、正确的顺序，结构上要浮现人们实际在做什么，而不是他们以为自己会做什么。新手创始人的常见错误，是问一个关于未来的泛泛开放问题（「你会用这种东西吗？」），而不是具体去问相关的过去（「上次你处理这个问题时发生了什么？」）。

Claude 也可以标出你草稿里哪些问题在引导受访者、哪些太宽、哪些很可能产生噪音而不是信号。Claude 还可以帮你设计追问，用来探查回避，或把重要问题上含糊的回答往下挖。

如果你的假设涉及不止一个角色，Claude 也可以为每个角色设计不同的问题集。财务经理和 CFO 对同一个问题的关系不同，单一访谈框架会把这个差别抹平。

- **练习：** 先亲手起草访谈问题，再让 Claude 审核。明确要求它标出任何引导性的、面向未来的、过宽的，或很可能得到社会期望答案而不是诚实答案的问题。然后让它为访谈中最可能出现回避的两三个时刻，各给一个追问探查。

#### 访谈后分析

每次谈话之后，用 Claude 做复盘：把笔记喂给它，让它指出哪些内容确认了你的假设，哪些挑战了假设，哪些真正出乎意料。当你积累了一批访谈之后，把全套访谈笔记交给 Claude Cowork，浮现反复出现的主题、矛盾，以及两个方向上最强的信号。然后再把这份综合输出拿回 Claude，让它标出：你自己对数据的解读，哪些地方可能是在把数据套进你想听到的模式，而不是数据里实际有什么。

- **练习：** 每做完五次访谈，让 Claude Cowork 综合你的笔记，产出两份清单：支持你假设的证据，以及挑战它的证据。如果第一份明显比第二份长，问 Claude：这种不对称反映的是数据里实际有什么，还是你希望找到什么。

### 客户触达和排期

用 Claude Cowork 自动化围绕建立联系人名单、做触达、安排用户访谈的操作性负担。

Claude Cowork 可以用你和 Claude 一起定义的目标画像（包括职位、公司类型和资历层级）去调研并汇编一份结构化潜在对象名单，以及经过核验的联系方式。然后它会按规模起草个性化触达邮件，每一封都按这个人的角色和情境来写。

回复进来之后，它通过 MCP 连接到 Gmail 和 Google Calendar，管理邮件线程、处理排期请求，并把访谈放到日历上。这个工作流会继续下去：Claude Cowork 按既定节奏生成跟进草稿（例如，对还没有回复的联系人做第七天跟进），并在每一步完成时更新你的跟踪表，让你始终知道每个潜在对象在流程里处在哪一步。

- **练习：** 把你已经验证过的访谈目标画像交给 Claude Cowork，让它建立潜在对象名单、起草个性化触达序列，并建一张跟踪表，列包括触达状态、跟进节奏和访谈完成情况。然后让它去跑协调工作，你把注意力放在准备谈话本身。

### 设计最终方案概念

你已经做完验证工作：问题是真实的，你知道谁有这个问题，而且你有一个证据支持的方案概念。用 Claude 从每个角度发展和挑战你的方案概念：缺口在哪里？存在哪些替代方案？要让这个方案在规模上成立，哪些事情必须为真？这是一个重要的现实检查点：这个设计是否真的针对验证过程揭示出来的那个问题，而不是你一开始假定的那个问题？

- **练习：** 把你的方案概念交给 Claude，让它找出这个设计最重度依赖的三个假设。然后问：每个假设要成立，哪些事情必须为真；如果其中任何一个不成立，后果是什么。

### 用 Claude Code 做一个轻量原型

现在到了有意思的部分：有了经过验证的假设，以及做过压力测试的方案概念，你终于可以动手做一个东西了。

这是 Idea 阶段里 Claude Code 真正进入画面的时刻。即使你一路上都在摆弄，现在才是你生成正式轻量原型的节点：把你的想法放到一个真实的人面前、并得到真实反应所需要的最小界面。

你现在做的还不是真实世界里的产品；你是在构造一个功能样本，用在客户和投资人的对话里。真实用户对一个他们实际能上手的东西作出反应，会告诉你许多问题—方案发现访谈给不了你的东西。在此之前，你在确认自己要解决的问题是真实的；现在，你是在请潜在用户去接触这个拟议方案。

- **练习：** 定义你的方案所依赖的那一个核心交互。让 Claude Code 只做那一个。做出来之后，把它放到五位来自你已验证目标画像的人面前，请他们试用。这五次谈话里学到的东西，决定你是继续做下去，还是回到起点重新设计。

走到 Idea 阶段的终点，是 AI 创业竞赛里往前跨出的一大步，因为你现在不是在赌一个直觉，而是在依据证据执行。接下来是 MVP 阶段。创始人的引导问题从「这件事值不值得做？」变成「我们到底该先做什么？」；AI 的主要角色也从调研搭档，转成施工队。
